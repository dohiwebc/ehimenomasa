## Headers and CSP

`functions/_middleware.js` attaches headers to normal pages, redirects, errors, static assets, and API responses, including future production `ehimenomasa.com` responses.

- `Content-Security-Policy` (enforced after the Report-Only browser checks).
- `X-Frame-Options: SAMEORIGIN`, CSP `frame-ancestors 'self'`.
- HTTPS: `Strict-Transport-Security: max-age=31536000`. No `includeSubDomains` or preload.
- `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()`.
- Additional `X-Content-Type-Options: nosniff`.

Allowed parent-document resource sources:

| Resource | Sources |
| --- | --- |
| Default | Same origin |
| Scripts | Same origin, `challenges.cloudflare.com`; no inline script, eval, or inline event handlers |
| Styles | Same origin, `fonts.googleapis.com`, existing inline styles |
| Fonts | Same origin, `fonts.gstatic.com` |
| Images | Same origin, `images.microcms-assets.io`, data images |
| Connections | Same origin, `challenges.cloudflare.com` |
| Frames | Same origin, Turnstile, `www.google.com/maps/`, `www.instagram.com`, `www.youtube.com/embed/` |
| Object embeds | None |
| Form actions / base URL / frame ancestors | Same origin |

YouTube is required by the existing video modal and was not removed. Existing inline styles are retained to avoid changing the design; `unsafe-inline` is permitted only for styles, never scripts. Third-party documents inside cross-origin frames have their own policies. Their internal Google/Instagram/CDN/ad/video requests do not require adding those origins to the restaurant's parent CSP.

Lifecycle: serve Report-Only first, open all 12 pages with real external resources and trigger the video modal, confirm zero parent CSP violations, then switch the default to enforcement and repeat. `CSP_MODE=report-only` remains available for rollback/diagnosis; it does not disable the other security headers. Browser tests capture `securitypolicyviolation` events locally; no remote CSP report collector was added.

The production hostname was simulated with local disk responses for the browser integration test, so no request was sent to the actual production site. Actual deployed preview responses are checked separately. Production DNS, TLS, dashboard overrides, and final production responses still require checking at the authorized production release.

References: [Cloudflare Turnstile CSP](https://developers.cloudflare.com/turnstile/reference/content-security-policy/), [Pages headers and Functions](https://developers.cloudflare.com/pages/configuration/headers/).

## Forms

- All three forms: `maxlength` name 50, phone 20, email 254, notes/PR 1000. Existing numeric/date/select controls keep their existing UI and constraints; backend lengths also cover their submitted display strings.
- Hidden `_website` text input, `tabindex=-1`, `autocomplete=off`, inaccessible container. Excluded from the confirmation summary, included in the API payload, never forwarded to Formspree. Any nonempty value is rejected.
- Only `reserve`, `takeout`, `recruit`; unknown type 404. Only POST; other methods 405 with `Allow: POST`.
- Exact HTTPS same-origin check against the production hosts, current Pages production host, or the fixed preview alias. No arbitrary `*.pages.dev`, wildcard CORS, null/missing Origin, cross-origin www, or foreign domains. CORS echoes only an allowed exact own origin, with `Vary: Origin`.
- 64 KiB body ceiling, checked against both declared and streamed actual byte counts, before parsing multipart or URL-encoded data. Oversized 413; unsupported or malformed body 400.
- Maximum 32 fields; duplicate keys, files, unknown fields, oversized field values rejected with 400, not silently dropped.
- Turnstile token required, at most 2048 characters. Server-side siteverify checks success, exact action and exact request hostname; failures, missing metadata, bad JSON, network failures, missing secret return 403. Timeout 10 seconds.
- Field limits enforced server-side before Turnstile calls or mail forwarding. Other short fields capped at 200; dates 10, times 5, party/age display strings 20, subject 200.
- `escapeHtml` also escapes `'` to `&#39;`.
